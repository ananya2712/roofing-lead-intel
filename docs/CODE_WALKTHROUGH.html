Architecture · Page 3 of 28 · Slide 3

03High-level architecture

System request path. The setup path (snapshot import) runs by command, outside page requests.
Diagram
Two paths: page requests at run time, and a one-time setup by command.
PathPartsBoundary
Request path · every page view and saveSales rep → browser → Next.js frontend (4 pages, typed API client, /api/v1 proxy) → Flask API (validation, services, scoring rules) → PostgreSQL (prospects, prospect_scores, leads)Pages call the typed client. Next.js forwards /api/v1 to Flask on the same origin. Flask validates input, runs services and queries, and returns JSON. A save commits one lead row; the page then reloads the list and counts. Late responses are ignored.
Setup path · one time, by commandGAF directory (external; blocks servers with 403) → browser, once → 2 snapshot JSON files (409 records, retrieved_at) → flask import-snapshot (validate, upsert, score)Validate each record, normalize phones and addresses, upsert by directory + GAF ID, then rescore only the imported rows. Leads are never changed. Invalid records are listed and skipped.
Excluded at run timeNo live GAF or AI call; no background jobs or cache; one shared workspace, no loginAll writes are short transactions in PostgreSQL. Runs as three containers locally (Docker Compose).
Current execution paths; comparisons are inferred except snapshot choice D1 and proxy choice D15.
PathImplementationWhy this boundaryAlternative / trade-off
Data ingestionGAF browser collection → JSON → CLI validation/upsert → stored scores.D1: one-time collection avoids a runtime dependency on blocked GAF scraping.Live API/feed: better freshness, but approved access and refresh policy are not available in the current implementation.
Browser requestTyped client → same-origin /api/v1 → Next.js rewrite → Flask route → service/query → PostgreSQL.D15: one browser origin avoids separate cross-origin configuration.Direct browser-to-Flask calls: workable, but require explicit CORS and deployment-origin management.
Save/status mutationValidate → service write → commit → response → reconcile UI.Commit defines persisted truth; UI pending/error state is not persistence.Optimistic UI alone cannot enforce identity or recover an ambiguous commit.
Service layoutModular monolith: routes, services, queries, models.Keeps HTTP, policy, and persistence responsibilities separate.Microservices introduce distributed failures and deployment boundaries without a measured need.

ChoiceWhy it fits this MVPCost / limitationAlternativeWhy the alternative is not used here
Next.js 14 + React + TypeScript + TailwindFile routes, typed pages, shared pastel tokens, same-origin API proxy.Separate frontend build; generated types do not validate HTTP at run time.Vite + React SPAAlso viable; a proxy and routing must be added by hand. REST + OpenAPI + generated TypeScript clientExplicit resource contracts and compile-time caller checks.Routes, schemas, YAML and generated types must stay aligned.GraphQL / handwritten fetch typesNo requirement for client-selected graph traversal. 06Flask vs FastAPI, and the REST design

Verdict: FastAPI would remove contract upkeep; Flask stays for the approved stack and the small API. Comparison inferred.
CriterionFlask (chosen)FastAPI
ValidationPydantic models called in each routePydantic built into function signatures
API contractopenapi.yaml by hand; 11 contract tests catch driftOpenAPI generated from code
AsyncSync WSGI, gunicorn 2 workers × 4 threads; short database callsNative async; helps many slow I/O calls
CLI and setupFlask CLI: import-snapshot, rescoreNeeds Typer or separate scripts
ErrorsOne handler set: ApiError, 404, 405, 422, 500Similar, with a built-in 422 shape
FitApproved stack; 8 endpointsStack change; little gain at this size

REST rules in this API

How the eight endpoints follow REST conventions.
RuleIn this API
Resources/prospects, /prospects/{id}, /prospects/stats, /leads, /leads/{id}/status, /overview, /health
MethodsGET for reads (6). POST for save and status change (2). PATCH returns 405 (D25).
Status codes200, 201, 404, 405, 409, 422; unexpected failures return a safe 500.
Versioned prefix/api/v1
One error shape{"error": {"code", "message", "details"}}
Stateless requestsFilters and pages in the query string.
Safe repeatSaving again returns 200 and adds no row.
Contractopenapi.yaml → generated TypeScript client (openapi-typescript, openapi-fetch).

ChoiceWhyAlternativeWhy not / limit
